LOQ-17502 — why a populate that fires only change is lost on Hyvä

Every field below is bound with a real Alpine x-model, exactly as Magewire rewrites Hyvä Checkout's wire:model.defer. "Component state" is what a Magewire commit would send to the server — if a populated value is missing from it, that value is already lost.

This page does not verify the fix. It never loads view/base/web/capture.js; the dispatch below is a model of it, written by hand. It demonstrates Alpine's binding behaviour — that a text input synced by x-model needs input, and that a value which never reached component state is lost on the next commit and morph. What exercises the real script is the automated suite: npm test over Test/js/, which loads the actual capture.js. A manual pass on a real Hyvä Checkout is still required; see Test/manual/LOQ-17502-manual-qa.md.
